# Wazuh SOC Home Lab

A hands-on cybersecurity lab built to explore Security Information and Event Management (SIEM), endpoint monitoring, vulnerability detection, and file integrity monitoring using Wazuh.

**Project status:** In Progress  
**Category:** Cybersecurity | Blue Team | SOC | SIEM

## Overview

This project documents my experience building and configuring a Wazuh security monitoring lab using VirtualBox, Ubuntu, and a Windows endpoint.

The objective is to understand how a SIEM platform collects endpoint information, displays security findings, and supports vulnerability investigation.

The lab is also being used to explore file integrity monitoring and the verification of security alerts.

## Lab Architecture & Environment

This lab uses a virtualized environment to explore security monitoring, endpoint event collection, and alert investigation using Wazuh. Ubuntu hosts the Wazuh monitoring components, Windows 10 serves as the monitored endpoint, and Kali Linux provides an environment for authorized security testing.

### Environment Specifications

| Component | Configuration |
|---|---|
| Host Operating System | Windows 11 |
| Hypervisor | Oracle VirtualBox 7.2.12 |
| Wazuh Manager | Ubuntu 24.04.4 LTS |
| Wazuh Version | 4.12.0 RC1 *(verify against the installed version)* |
| Monitored Endpoint | Windows 10 Home 22H2 |
| Windows Build | 19045.2965 |
| Security Testing Environment | Kali Linux |
| Virtual Network | NAT Network |
| Network Address Range | `10.0.0.0/24` |

### Architecture Overview

```text
             Windows 11 Host
                    |
            Oracle VirtualBox
                    |
              NAT Network
                    |
       +------------+------------+
       |            |            |
       v            v            v
 Ubuntu VM      Windows 10 VM   Kali Linux VM
 Wazuh Manager  Wazuh Agent     Security Testing
       |            |
       |<-----------|
       |
 Wazuh Dashboard
 Security Alerts
 Event Analysis
```

**Component roles:**
- **Ubuntu VM:** Runs the Wazuh monitoring infrastructure and provides access to the security dashboard.
- **Windows 10 VM:** Generates endpoint telemetry collected by the Wazuh agent.
- **Kali Linux VM:** Supports controlled security experiments within the authorized lab environment.
- **VirtualBox NAT Network:** Provides network connectivity between virtual machines according to the configured network and firewall rules.

The lab is designed to investigate endpoint security events, analyze alerts, and understand how a SIEM platform supports security monitoring.

For installation procedures, agent configuration, and connectivity verification, refer to the dedicated setup documentation.

## Setup and Configuration

The lab setup involves installing and configuring Wazuh, connecting the Windows endpoint to the manager, and verifying communication through the dashboard.

The main configuration stages include:

1. Preparing the virtual machines and configuring their network connectivity.
2. Installing the Wazuh manager, indexer, and dashboard on Ubuntu.
3. Installing and configuring the Wazuh agent on Windows 10.
4. Registering the endpoint with the Wazuh manager.
5. Verifying agent connectivity and the collection of security events.

### Initial Observations

During the initial monitoring stage, the Wazuh dashboard displayed multiple critical-severity alerts, including 18 critical cases observed during the investigation.

These alerts require individual examination to determine their underlying causes and relevance. A critical severity rating does not, by itself, establish that a system has been compromised or that every finding represents an exploitable vulnerability.

The investigation focuses on understanding the reported events, validating findings, and documenting relevant evidence.

## Vulnerability Monitoring

The Wazuh vulnerability dashboard displays vulnerability findings associated with the monitored Windows endpoint.

The next stage is to investigate selected findings by recording:

1. CVE identifier and severity.
2. Affected application, package, or operating-system component.
3. Installed version and applicable fixed version, where available.
4. Vendor advisory or other authoritative evidence.
5. Recommended remediation.
6. Validation results after remediation, if performed.

A vulnerability finding is an investigation lead; it does not by itself establish that a system has been compromised or that a vulnerability is exploitable in the lab.

## File Integrity Monitoring

File Integrity Monitoring is a planned verification task in this project.

The test will use a dedicated, non-sensitive directory on the Windows endpoint:

1. Configure Wazuh to monitor the directory.
2. Restart the agent if required by the configuration change.
3. Create a test file.
4. Modify the file.
5. Delete the file.
6. Check the Wazuh dashboard for the corresponding events.
7. Record the results and supporting screenshots.

The FIM section will be marked complete after the expected events have been verified.
